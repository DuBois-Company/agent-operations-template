# PROGRESS.md — the narrative companion to example/graph.yaml

The graph holds state and structure. This file holds what the graph cannot:
why a decision went the way it did, what was actually run to verify a node,
and what each session grounded itself on before it touched anything. Entries
are keyed to node ids in example/graph.yaml and are never reordered — a
correction is made in place and annotated, so the record of being wrong
survives the fix.

Fiction, all of it. Today, in this project's story, is 2026-05-14.

## Rationale

- 2026-03-12 (initialization): the work was a web application's auth service with a clear dependency chain and more than one session of runway, so it was set up as a graph project rather than a task list. Cap set with the team at 400k tokens and written to B1. Agents registered as fable5 planning and reviewing, opus5 implementing, sonnet5 on prose.
- 2026-03-16 (D1): sessions use JWT with 24 hour expiry. A shorter lifetime was argued for and lost: without refresh rotation in the first milestone, a 2 hour token would have logged the team out mid-session with no recovery path, and a silent auto-renew would have been a worse answer than a documented 24 hours. The decision is written once, in the config module, so nothing re-derives it.
- 2026-03-19 (D2): signing stays HMAC-SHA256 with a single shared secret. Asymmetric signing buys key distribution the project does not need yet, and it would have made T1 a two-session node instead of a one-session node. Recorded with a revisit condition rather than left as a silent assumption.
- 2026-03-24 (T1): the compact JWS form is implemented directly against the standard library instead of pulling a JWT dependency. The example has to run on a bare interpreter, and the security-relevant part — refusing the algorithm the token names for itself — is four lines whether it is written here or imported.
- 2026-04-08 (T3): every rejection raises a distinct exception rather than returning a falsy value. A caller who forgets to check a boolean lets a forged token through; a caller who forgets to catch fails closed. That asymmetry decided it.
- 2026-04-27 (milestone_2026-04_auth_core): T1 through T6 were archived with full node bodies, not ids. An id-only archive would have destroyed exactly the telemetry L1 and L3 rest on, and those lessons are the reason the archive is worth keeping at all. Durable nodes — D1, D2, the artifacts, the budget — stayed in the live list so a full read stays cheap.
- 2026-04-27 (X1): the exploration budget went on one hypothesis, drawn from the top of the backlog rather than invented: can the cheapest tier implement a config-only node. It was placed on T7, which had slack behind it, so a loss would have cost one retry and nothing on the critical path.
- 2026-04-28 (D3): a framework advisory about session cookie defaults arrived by email. It is external content, so it was written down tainted the day it arrived and explicitly barred from informing dispatch. T10 was drafted but held.
- 2026-05-04 (D3, clearance): the claim was re-derived from the framework's own documented defaults rather than accepted on the advisory's word, and pinned by a test that fails if the flag changes. fable5 ran `python -m unittest example.tests.test_middleware -q`, exit 0, and recorded the clearance inline on the node — what was checked, when, by whom. Only then did D3 become internal and inform T10.
- 2026-05-05 (X1, scored): the prediction held. T7 passed review on the first attempt at 11k tokens against a 0.55 prediction, and the result was written up as L2. L2 is a candidate, not active: one project is one attestation, and the rule needs a second, separate project before it changes routing by default.
- 2026-05-07 (L3): two nodes have now needed a second attempt — T3 in April, T8 this week — and both were boundary work whose acceptance criterion named a test module and not the case that mattered. The lesson is about how criteria are written, not about who wrote the code, so it acts on criteria and never on the bar.
- 2026-05-10 (T9, escalation): opus5's first attempt left revoked tokens verifying inside the clock-skew window. The bar does not move for cost, so the node was escalated to fable5 rather than accepted with a known hole, and the added 21k is recorded on the node and in B1. Escalating after one attempt rather than three is the part worth repeating.
- 2026-05-12 (planning): T13 has no path to T11 or T12, so it runs in parallel with either. T14 stays blocked behind T12 on purpose — there is nothing to sweep until rotation exists, and dispatching it early would have bought a stub that the real node then had to unpick.
- 2026-05-14 (B1): spend stands at 265k against a 400k cap, with nine of fourteen task nodes done, T10 awaiting review, and four still to run. That is ahead of plan but not tripped. If T11 and T12 land inside their estimates the project closes under the cap; if either needs an escalation, the next review replans for a cheaper path to the same bar rather than lowering the bar.
